# AGENTS.md

Guidance for AI coding agents working in this repository.

## What this is

A Node.js native addon, written in Rust with [napi-rs](https://napi.rs), that converts images to WebP using
[`libwebp-sys`](https://crates.io/crates/libwebp-sys) (raw FFI bindings to Google's libwebp).

**Current state:** the repo is still the unmodified `@napi-rs/package-template` scaffold. `src/lib.rs` only exports
`plus_100`, `libwebp-sys` is not yet a dependency, and `README.md`, `package.json` (`description`, `repository`), the
tests, and the benchmark still refer to the template. The conversion logic described below is the target design,
ported from the reference implementation in
[pedromneto97/image_optimizer/rust](https://github.com/pedromneto97/image_optimizer/tree/master/rust) (a Rust → C FFI
library consumed from Dart/Flutter).

once `libwebp-sys` is added, a C compiler (the crate compiles libwebp's C sources at build time).

## Architecture

### Rust ↔ JS boundary (napi-rs)

- `src/lib.rs` is the crate root, built as a `cdylib`. Any `#[napi]` item becomes a JS export; snake_case Rust names
  are exposed as camelCase (`plus_100` → `plus100`).
- `index.js` (platform loader) and `index.d.ts` (TypeScript types) are **generated by `napi build`**; never edit them
  by hand. Rebuild and commit them whenever the exported Rust API changes.
- The build produces `webp-converter.<platform>.node` in the repo root (name from `napi.binaryName` in
  `package.json`). `index.js` picks the right binary at runtime, including glibc vs. musl detection on Linux.
- Supported targets are listed in `package.json` → `napi.targets`, and the CI build matrix must match them.
  Windows MSVC links the CRT statically (`.cargo/config.toml`).
- `build.rs` only calls `napi_build::setup()`. Unlike the reference project, there is no cbindgen or C header, because
  napi-rs generates the binding layer.
- Crate root has `#![deny(clippy::all)]`, so clippy warnings fail the build.

### Conversion design (from the reference implementation)

The reference `converter.rs` is the blueprint. When porting it, keep these points:

- **Input detection:** sniff magic bytes (`image::ImageReader::with_guessed_format`) instead of trusting the file
  extension. GIF takes the animated path. Everything else is decoded with the `image` crate and must be `Rgb8` or
  `Rgba8` (other color types are rejected).
- **Still images:** `WebPEncodeRGB` / `WebPEncodeRGBA` with stride `width * 3` / `width * 4`. The output buffer is
  allocated by libwebp and must be released with `WebPFree`.
- **Quality sweep:** encode at several qualities from `min_quality` to 100 and keep the candidate with the lowest
  `bytes / max(quality, 1)`. Still images step by 2. Animations try at most 4 candidates, because each candidate
  re-encodes every frame. Clamp `min_quality` to 100.
- **Animated GIF → animated WebP:** `WebPAnimEncoder` (`…NewInternal` / `…OptionsInitInternal` with
  `WebPGetMuxABIVersion()`), `allow_mixed = 1`, and the GIF loop count capped at `u16::MAX`. Frame timestamps are
  _start_ times. Delays have a 10 ms floor. A final `WebPAnimEncoderAdd(enc, NULL, ts, NULL)` terminator is required
  before `WebPAnimEncoderAssemble`. The GIF is re-decoded per candidate instead of caching frames, to bound memory.
- **Frame count:** libwebp merges identical consecutive frames, and if only one frame remains it writes a still WebP.
  Report the frame count by demuxing the output (`WebPDemuxGetI(…, WEBP_FF_FRAME_COUNT)`), not by counting decoded
  frames. A GIF that decodes to a single frame falls back to the still path.
- **Limits:** check both axes against `WEBP_MAX_DIMENSION` (16383) yourself, because the anim encoder only checks
  total area. Before `WebPPictureImportRGBA`, check that the RGBA buffer is at least `width * height * 4` bytes;
  libwebp reads straight off the pointer.
- **Memory safety:** every libwebp-owned resource is wrapped in a small RAII type with `Drop` (`WebPFree`,
  `WebPAnimEncoderDelete`, `WebPPictureFree`, `WebPDataClear`, `WebPDemuxDelete`) so `?` early returns cannot leak.
  The demuxer borrows the assembled bytes, so keep it lifetime-tied to them.
- **Errors:** the reference maps a `ConverterError` enum to integer codes for Dart. Here, convert errors to
  `napi::Error` with a descriptive message instead of numeric codes.
- **Node-specific:** encoding is CPU-heavy (a full quality sweep). Expose it as a napi `AsyncTask` / `async fn` so it
  runs on the libuv threadpool and does not block the event loop. Accepting and returning `Buffer`s, not only file
  paths, fits Node usage.

## Conventions

- Rust uses **2-space indentation** (`rustfmt.toml`), unlike the reference project's 4. Edition 2021.
- JS/TS formatting (oxfmt): 120 columns, no semicolons, single quotes, trailing commas.
- Tests are TypeScript, run through `@oxc-node/core/register` with `__test__/tsconfig.json` (ESM). The root
  `tsconfig.json` excludes `__test__`.
- Template leftovers to clean up when they are touched: the `package-template.*` WASI file names in
  `__test__/index.spec.ts` and `.oxfmtrc.json`, the README, and the `package.json` metadata.

## Release

CI (`.github/workflows/CI.yml`) lints, builds every target, tests on Node 22/24/26, then publishes. Publishing happens
only when the head commit message is a bare semver: `x.y.z` publishes to `latest`, and `x.y.z-…` publishes to `next`.
Use `npm version <bump>` and push. Do not run `npm publish` manually. CI needs the `NPM_TOKEN` secret.
